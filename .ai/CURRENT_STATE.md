## What Works
- `sprite-vault/` hosts the static Sprite Vault Tracker catalog mirror for `https://misaellandero.com/sprite-vault/manifest.json`.
- `sprite-vault/control.json` lets Sprite Vault Tracker switch between automatic, SpriteLocker-only, and HomeWeb-only catalog sources.
- `Apps/SpriteVaultControl/Index.html` is a static manual control panel for editing `control.json`, dispatching mirror refreshes, viewing backups, and previewing the iPhone catalog data.
- `.github/workflows/update-sprite-vault-mirror.yml` regenerates the mirror every 12 hours and can be run manually.
- `Tools/SpriteVaultMirror/generate_mirror.py` creates backups in `sprite-vault/backups/` before replacing a changed catalog.
- `Tools/SpriteVaultMirror/generate_mirror.py` validates with `py_compile` and generates valid JSON files.
- Public GitHub Pages links should use explicit file paths with exact casing, for example `/Apps/PetPal/index.html` rather than `/Apps/PetPal`.
- `Apps/Cota/` is a Firebase-backed wish list ("Cota Waitlist") for a separate pet-care app (iOS/Web/Android), not to be confused with `Apps/PetPal/` (a static landing page with no signup form). Signups write to Firestore `cotaWaitlist` (per-email doc) in the `misaellanderoweb` Firebase project via `Apps/Cota/assets/js/waitlist.js`.
- `Apps/Cota/index.html` now also shows a public live counter (total signups + per-platform breakdown, including the new "iOS beta (TestFlight)" option) backed by a PII-free `cotaWaitlistStats/summary` Firestore doc, kept in sync via an atomic transaction in `waitlist.js`.
- `Apps/Cota/admin.html` + `Apps/Cota/assets/js/admin.js` is a Firebase Auth-gated admin dashboard that lists every wish list entry and recomputes counts live from the raw `cotaWaitlist` collection.
- `Apps/Revisits/index.html` now has a "Use on the Web"/"Usar en la Web"/etc. button (`assets/js/web-install.js`) next to the App Store CTA: on Apple devices (iOS/iPadOS/macOS) it redirects straight to the App Store listing; on Windows/Android/other it opens a Bootstrap modal with platform-specific PWA install steps linking to `Apps/Revisits/web/index.html`. This landing page itself is static English copy (`lang="en"`, preserved as-is) — the button/modal text is NOT part of that fixed copy, so it carries its own compact 18-language translation table in `web-install.js` (button label, modal title, "Open Revisits Web"/"Close" buttons, and the 3 sets of install steps) and auto-detects from `navigator.languages`/`navigator.language`, falling back to English (the page's own language) rather than Spanish. This was a follow-up fix after the user spotted the button/modal stuck in Spanish while the rest of the English page wasn't — the two i18n systems (this one and the PWA's `js/i18n.js`) are intentionally separate since this is a classic script on a static page, not an ES module in the PWA.
- `Apps/Revisits/web/` is now a functional local-first PWA port of the native Revisits app (vanilla JS ES modules, no framework/build step, IndexedDB storage, no server/CloudKit sync). Domain model mirrors the native Core Data schema (`territories`, `revisits`, `visits`, `services`, `dayGoals`, `reports`, `medals` — see `js/db.js`). Features: **Revisitas** tab (`js/views/revisits.js`) — list with search + Todos/Estudio/Revisita/Vencidas filters, full add/edit form (persona type + emoji, territorio with inline creation, Estudio/Revisita toggle, teléfono, referencias de casa, próxima visita, recordatorios, **Ubicación**), optional initial-visit section, detail view with visit-history log and "Nueva visita" (Biblia/Video/Publicación source picker with dynamic reference label, próxima visita, "Contar como revisita"). **Informes** tab (`js/views/reports.js`) — Día/Semana/Mes/Año period stats vs. goal, a resilient-across-reloads timer (duration presets, live Estudios/Publicaciones/Videos/Revisitas counters, Registrar writes a report and awards medals), manual report form, and a Historial list with delete. **Metas** tab (`js/views/goals.js`) — service types with a monthly goal + per-weekday goals, Mes/Año progress (Año calendario vs. Año de servicio Sept–Aug), a month calendar heatmap (goal-met/goal-missed per day) reusing the ported `medal_day/week/month/year.png` art, and auto-awarded medals (day→week→month→year priority, deduped per period) in `js/store.js`'s `computeAndAwardMedals`. **Ajustes** tab (`js/views/settingsView.js`) — a language picker, toggle which counters show (pubs/videos/returnVisits), Notification API permission for due-reminder/timer-goal alerts (`js/notifications.js`), and JSON export/import/reset backup (since there's no cloud sync). Art ported from the native app (downscaled): `assets/art/medals/*.png` (128×128, from 1024×1024 originals) and `assets/art/houses/casa_{estudio,revisita}_1-6.png` (house illustrations used as revisit list avatars, matching the native app's random 1–6 `houseIcon`). The SF Symbol export SVGs for "Estudio"/"Revisita" were NOT portable (Illustrator template artboards with guide layers, not clean standalone glyphs) — Font Awesome icons are used instead. `sw.js` now precaches the full local app shell (bumped to `revisits-web-v3`).
- **Geolocation** (`js/geo.js`): a revisit's edit form has a "Usar mi ubicación actual"/"Actualizar ubicación" button that captures GPS coordinates via the browser Geolocation API, stores them on the revisit record (`mapLat`/`mapLng`), and best-effort reverse-geocodes them via the free OpenStreetMap Nominatim API to prefill "Referencias de la casa" when empty (fails silently offline/blocked — never blocks saving). The detail view shows an embedded OpenStreetMap iframe (no API key) plus "Ver en el mapa" and "Cómo llegar" (opens Google Maps) links when a location is set, and a "Quitar ubicación" option to clear it.
- **Full i18n, 18 languages** (`js/i18n.js` + `js/i18n-strings.js`): the same language set the native app ships (es, en, de, fr, it, pt, nl, el, pl, ru, tr, uk, vi, th, id, hi, ja, ko). Every UI string, the 14 `personTypes`, the 3 `sources`/`sourceRefs`, the 7 weekday names, and the 4 medal labels are translated per language (148 keys × 18 languages, all verified present programmatically). A language picker lives in Ajustes; the initial language auto-detects from `navigator.language` (falling back to Spanish, the app's source language) and persists via `localStorage`; switching re-renders the whole app instantly, updates `document.documentElement.lang`, and `utils.js`'s date formatters (`formatDateLong`/`formatDateShort`/`monthLabel`) switch locale (e.g. `ja-JP`) automatically. Only display labels are localized — stored data values (`visitType: 'Estudio'|'Revisita'`, `personType`/`toolboxPub` indexes, medal `type` keys) stay as fixed internal tokens so existing records and filters keep working across a language switch. English and the widely-spoken European languages (de/fr/it/pt/nl/pl/ru/tr) reuse the native app's own translated strings from `Shared/Localizable.xcstrings` where an exact match existed; every other string — including all of el/uk/vi/th/id/hi/ja/ko — was translated directly by the assistant and has not been reviewed by a native speaker.
- **Territorios tab + Leaflet** (`js/views/territorios.js`): a 5th tab (now first, matching the native app's order) showing a real interactive OpenStreetMap map (Leaflet 1.9.4, loaded via jsDelivr CDN — the PWA's first external JS dependency, approved by the user) with a colored circle marker (green Estudio / blue Revisita) for every revisit that has a saved location; tapping a marker's popup link opens that revisit's detail sheet (`revisits.js` now exports `openDetail`). Falls back to a translated "couldn't load the map" message if Leaflet fails to load (offline, blocked, ad-blocker) rather than throwing. No SRI hash on the CDN `<link>`/`<script>` tags — the sandbox's network policy blocked fetching jsDelivr so the real hash couldn't be verified, and a guessed/wrong hash would silently break the map for every user, which is worse than no integrity check on a well-known CDN.
- **In-app install prompt** (`js/install.js`): previously the only install entry point was the marketing landing page's button; now the PWA itself listens for the `beforeinstallprompt` event (Chrome/Edge/Android) and shows a dismissible bottom banner ("Instala Revisits Web" / Instalar / Ahora no), remembering a dismissal in `localStorage` so it doesn't nag every visit. Ajustes also has a permanent "Instalar aplicación" card: shows an "Instalar app" button when the browser has offered the prompt, "Ya está instalada ✓" when running standalone (`display-mode: standalone`), or generic manual instructions otherwise (e.g. iOS Safari, which never fires `beforeinstallprompt`).
- **Material Design pass** (`css/app.css`): dark mode via `@media (prefers-color-scheme: dark)` (follows the OS/browser setting only, no manual toggle, per the user's choice) — this surfaced and fixed a real bug where `.modal-sheet` (every form/detail sheet in the app) had a hardcoded `background: #fff`, which would have made all text unreadable in dark mode; also fixed hardcoded white/missing backgrounds on the search input and language `<select>`. `.segmented` (filter/period/source pickers) restyled from a single shared track into individual Material-style filter chips. Added elevation shadow tokens (`--elevation-1`/`--elevation-3`) on cards/FAB, a Material 3-style pill indicator behind the active tab bar icon, and subtle `:active` press feedback (scale/tint) on buttons, the FAB, and list items.
- **Icon audit / bug fix**: found and fixed 8 `<i class="fas fa-...">` icon names across the app (`fa-gear`, `fa-calendar-days`, `fa-map-location-dot`, `fa-location-crosshairs`, `fa-diamond-turn-right`, `fa-rotate-left`, `fa-triangle-exclamation`, `fa-xmark`) that are Font Awesome **6** names — this app loads Font Awesome **5.6.3**, where those icons don't exist under those names, so they were almost certainly rendering as invisible/blank glyphs since the icons were first added earlier this session. Renamed to their real FA5 equivalents (`fa-cog`, `fa-calendar-alt`, `fa-map-marked-alt`, `fa-crosshairs`, `fa-route`, `fa-undo`, `fa-exclamation-triangle`, `fa-times`). Confirmed fixed by the user on their real Android phone (all 5 tab icons now render correctly).
- Fixed `Apps/Revisits/web/js/views/reports.js`'s Informes "Historial" list rows to also show Publicaciones/Videos counts (previously only Estudios/Revisitas showed, even though the data was always saved) — this was the user's reported bug after testing on their Android phone.
- **Timer redesign** (`js/views/reports.js`): the running-timer controls were just a small "Reiniciar" text button plus "Registrar", with no way to pause — the user found this confusing. Added real pause/resume: timer state now tracks `running`/`accumulatedMs` alongside `startTime` (old sessions without these fields default to running, so no migration needed), and `elapsedMs(state)` computes total elapsed time whether running or paused. Three big, equally prominent buttons while a session is active: **Reiniciar** (discards the session), **Pausar**/**Reanudar** (toggles, freezes the displayed time and stops the tick interval while paused), and **Registrar** (unchanged, opens the report form prefilled with the accumulated time). The discard button was briefly relabeled "Ignorar" with a confirm-before-discard dialog, but the user correctly called that out as a bad translation/invented behavior — checked the native app's `CircularTimerView.swift` directly and matched its real string ("Reiniciar"), its icon (SF Symbol `arrow.clockwise.circle.fill` → Font Awesome's `fa-redo`), and its actual logic (`restart()` fires immediately on tap, no confirmation dialog at all in the native app). Removed the now-dead `btnIgnore`/`confirmIgnoreTimer`/`confirmRestartTimer` i18n keys (18 languages each) instead of leaving unused translations behind.
- **Empty-state "add" buttons**: every list-style empty state that represents something the user can directly create now has its own embedded button next to the explanatory text, not just a separate header/FAB button elsewhere — Revisitas ("Agregar revisita"), Informes' Historial ("Registrar"), Metas' service list ("Nuevo"), and Territorios' no-locations state ("Agregar revisita", which switches to the Revisitas tab and opens the form). Medals' empty state and a day-detail's empty state were left as pure information (nothing to directly "add" there).

## Known Issues
- ⚠️ **TEMPORARY**: `Apps/Revisits/assets/js/web-install.js` has `APPLE_REDIRECT_ENABLED = false` so the user can test `Apps/Revisits/web/` directly on their own iPhone. While this is `false`, Apple visitors clicking "Use on the Web" land in the PWA instead of being sent to the App Store. **Set it back to `true` once iOS testing is done** — real end users on iPhone/iPad/Mac should be redirected to the native App Store listing, not the web app.
- `Apps/Revisits/web/` intentionally does not replicate everything the native app has: no hand-drawing/PencilKit notes, no CloudKit sync or multi-device backup (JSON export/import only), and no real push notifications when the app/tab is closed (Notification API only fires while the page or its service worker is alive). The medal-award math (day/week/month/year goals derived from `Service.timeGoal` + `DayGoal`) mirrors the native logic but skips its legacy 70-hour `@AppStorage` fallback for when zero services are defined — in the web port, at least one service must be created before medals can be earned.
- Geolocation reverse-geocoding calls the public Nominatim API directly from the browser with no API key and no custom `User-Agent` (browsers can't set that header) — fine for personal/low-volume use, but it's the one place this app depends on a third-party network service; it fails silently (no address prefill) if offline, blocked, or rate-limited, and was untestable in this sandbox (its own network policy blocks `nominatim.openstreetmap.org`, confirmed via Playwright — the button, coordinate capture, and map/directions links were verified instead, which don't depend on it).
- The Territorios map (Leaflet + OpenStreetMap tiles) needs a live internet connection — neither Leaflet itself nor the map tiles are precached by `sw.js` (same reasoning as the Font Awesome CDN: precaching a cross-origin resource risks failing the whole service-worker install if that origin ever doesn't support the exact CORS mode `cache.addAll` uses). Offline, the Territorios tab shows the "couldn't load the map" fallback message instead of a blank/broken screen.
- Translation quality: the 10 languages not covered by the native app's own `Shared/Localizable.xcstrings` for a given string (notably all of el/uk/vi/th/id/hi/ja/ko, plus some newer web-only strings in every language) were translated directly by the assistant, not by a human native speaker or the professional localizers behind the native app's existing translations — treat them as good-faith machine translation, not verified copy.
- Public GitHub Pages must publish `sprite-vault/control.json` and `Apps/SpriteVaultControl/Index.html` before the app can use the control panel in production.
- Cota's Firestore security rules (managed in the Firebase console, not in this repo) still need updating for the new stats/admin features — see the 2026-09-16 (2) hotfix entry in `.ai/TASK_LOG.md` for the exact rules needed (confirmed against the user's actual live rules). Until applied, waitlist signups themselves now work fine (fixed in the hotfix), but the public counter stays at 0 and the admin dashboard (`Apps/Cota/admin.html`) can't load any data.
